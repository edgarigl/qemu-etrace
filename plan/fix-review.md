# Assembly coverage review remediation plan

## Goal

Make LCOV line and function coverage for assembly code complete enough to be
auditable without weakening the distinction between facts established by the
ELF, DWARF, and execution trace.

The work should fix the three implementation defects identified by the x86
assembly audit:

1. DWARF end-sequence rows are treated as executable source locations.
2. Function declarations require a usable source row at symbol byte zero.
3. Line coverage is built only inside nonzero-sized ELF symbols.

It should also improve the inventory of sized functions generated by assembler
macros. Zero-sized text labels need a conservative policy rather than blindly
turning the range up to the next symbol into a function.

The raw execution trace is not the problem addressed here. Execution-range
accuracy is part of the ETrace contract and is handled independently by the
QEMU producer work in [`branch-mcdc-cov.md`](branch-mcdc-cov.md).

## Current data-flow problems

### Symbol lookup defines the coverage universe

`etrace_process_exec()` splits every executed range through
`sym_lookup_by_addr()`. `sym_update_cov()` then stores byte counters inside the
selected `struct sym`. Addresses not contained by a nonzero-sized symbol are
sent to the synthetic unknown symbol and discarded for source coverage.

`sym_find()` uses the half-open interval `[sym.addr, sym.addr + sym.size)`, so a
zero-sized text symbol can never match. Inferring its size from the next symbol
inside this lookup would be unsafe: aliases can share addresses, symbols can
belong to different sections, and an assembly label is not necessarily a
function.

### DWARF rows are attached only at their exact addresses

`sym_build_linemap()` parses `dwarfdump -l` output and attaches each row to the
symbol containing that exact address. It does not model the DWARF line
program's `[row.address, next_row.address)` interval semantics. A row emitted
for the first expansion of an assembler macro therefore does not cover later
symbols in that expansion range.

The parser also ignores the `ET` marker. An end-sequence row is consequently
attached to a symbol beginning at the sequence end, even though that row is a
terminator and describes no executable source location. The remembered source
filename is not reset at the sequence boundary.

### Function declaration lookup examines only byte zero

`gcov_find_decl_line()` only examines `s->linemap->locs[0]`. A sized function
whose first instruction has no line row is omitted even when a valid
non-inlined row exists later in the symbol. This affects
`common_interrupt` and `handle_ist_exception`.

### Line and function emission are coupled

`gcov_process_sym()` simultaneously builds line counts and adds functions to
source files. This makes it impossible to report source lines outside symbols
and encourages source ownership to be inferred from a function symbol. Line
coverage and function coverage need separate collection passes.

## Required semantic model

Keep three independent inventories:

1. **Executable ranges** come from allocated executable ELF sections and bound
   where machine-code coverage may be attributed.
2. **Source-line ranges** come from DWARF line-program sequences. A normal row
   owns the half-open address interval up to the next row in the same sequence.
   An end-sequence row closes the prior interval and owns no address.
3. **Functions** come from ELF function symbols with defensible bounds. Their
   hit policy is independent of which source line supplies the LCOV `FN`
   declaration.

Execution observations update an address-indexed coverage store independently
of symbols. LCOV line records are then produced by intersecting executed
addresses with source-line ranges. Function records are produced by
intersecting function symbols with eligible source locations and querying the
entry or source hit policy.

The implementation must never carry a source row across any of these
boundaries:

- a DWARF end-sequence marker;
- an executable ELF section boundary;
- an address regression that begins a new line-program sequence;
- an unmapped address gap not covered by a line row.

Multiple source locations at one address must remain representable. Inline
locations and discriminators must not be collapsed into a single arbitrary
owner.

## Phase 1: Add deterministic assembly fixtures

Add small x86 assembly fixtures rather than depending on the retained Xen image
for every test. Build them with explicit `.file`, `.loc`, `.type`, and `.size`
directives and a linker script where adjacency matters.

The fixtures should contain:

- a sized function with one or more leading bytes before its first source row;
- two adjacent source sequences whose end/start addresses are equal;
- an unreachable instruction immediately before an end-sequence address;
- several differently named sized functions emitted by one `.irp` or `.rept`
  body with only the macro invocation's line row;
- an executed zero-sized text label outside every nonzero-sized function;
- a discarded input section with residual debug information.

Capture and assert the relevant ELF symbols and decoded line rows before using
the fixtures for coverage assertions. Keep this preparatory commit passing: it
should assert fixture structure, while each corrected coverage expectation is
introduced with its implementation change. If installed assembler or
`dwarfdump` versions cannot reproduce a case reliably, add a parser-level
textual fixture for that case and keep the ELF integration test conditional.

### Phase 1 acceptance criteria

- Every fixture documents the exact symbol and line-table shape it exercises.
- Fixture-shape tests pass without changing production behavior.
- The zero-sized and discarded-section cases are distinguishable.
- The variable-length x86 regression remains unchanged.

## Phase 2: Parse DWARF line sequences explicitly

Refactor the `dwarfdump -l` parser out of `sym_build_linemap()` into a
unit-testable row parser. A parsed row should contain at least:

```c
struct dwarf_line_row {
        uint64_t address;
        const char *filename;
        unsigned int line;
        unsigned int discriminator;
        bool is_stmt;
        bool end_sequence;
};
```

Do not detect flags with unrestricted substring searches. Tokenize the flags
between the closing source-position bracket and `uri:` so `ET` is recognized
as a complete flag. Preserve the current filename only within one sequence.

When an end-sequence row is received:

1. close the preceding normal row's interval at the end-sequence address;
2. do not create a location for the end-sequence row itself;
3. clear the current filename, line, discriminator, and sequence state;
4. require the next sequence to establish its own source context.

Reject malformed decreasing or overflowing intervals with a diagnostic. An
address reset after an end marker is valid and starts a new sequence.

### Phase 2 acceptance criteria

- An end-sequence address has no source location of its own.
- The next symbol cannot inherit the preceding sequence's filename or line.
- Adjacent compilation units remain independent even when their addresses are
  equal at the boundary.
- Multiple rows at the same address remain deterministic and do not create a
  negative or wrapping interval.
- Parser tests do not require a particular host compiler or linker.

## Phase 3: Fix function declaration lookup

Change `gcov_find_decl_line()` to scan forward through the complete sized
symbol for the first address containing an eligible source location.

Eligibility requires:

- the requested source filename;
- a nonzero line number;
- no `LOC_F_INLINED` flag;
- a row that is not an end-sequence marker.

At the first eligible address, choose deterministically among aliased locations
at that address. Do not choose a numerically smaller line from a later address,
and do not change entry-hit counting: `FUNCTION_HIT_ENTRY` still reads coverage
at the symbol's first byte.

### Phase 3 acceptance criteria

- A function with unmapped leading padding receives an `FN` record from its
  first valid body row.
- Its `FNDA` count still reflects entry at the ELF symbol address.
- `common_interrupt` and `handle_ist_exception` are emitted in the reviewed Xen
  report.
- Aliases with the same name and declaration line remain deduplicated.
- A location from another file or an inline instance cannot become the
  declaration merely because it occurs first.

## Phase 4: Materialize DWARF row intervals inside sized symbols

Replace exact-address line attachment with line-sequence intervals. For each
normal row, apply its location over `[row.address, next_row.address)`, clipped
to executable sections and to each overlapping sized symbol. Walk across
symbol boundaries rather than resolving only the interval's first address.

Keep line-count aggregation explicit. Filling every byte with the same row
must not multiply an LCOV line count by instruction width. Define and test the
aggregation rule before changing it; for hit/dead reporting, any executed byte
in an interval is sufficient, while execution counts should use a documented
maximum or event-based rule rather than accidental byte summation.

This phase should recover macro-generated sized functions when a line row for
the macro invocation legitimately spans their code. It must not invent a
mapping after the sequence ends.

### Phase 4 acceptance criteria

- Every address in a normal line-row interval has the intended source mapping.
- No address at or after an end-sequence marker inherits the preceding row.
- An interval crossing several sized symbols is clipped and applied to each.
- Generated IDT and indirect-thunk symbols covered by a valid row interval gain
  function records, even when GAS emitted no row at each symbol entry.
- A wider instruction or interval does not inflate its source-line count.

## Phase 5: Add symbol-independent source coverage

Introduce an executable-image coverage map owned by the symbol store but not
partitioned by symbols. Populate its bounds from ELF sections marked allocated
and executable. Prefer the existing BFD dependency over parsing human-readable
`objdump` output.

The map should provide operations equivalent to:

```c
bool image_coverage_add_range(store, start, end, count);
uint64_t image_coverage_at(store, address);
bool image_range_is_executable(store, start, end);
```

Update normalized ETrace execution ranges in this map before symbol lookup.
Continue updating per-symbol totals temporarily for cachegrind, QCOV, and
compatibility, but make LCOV line emission consume the image map and DWARF line
intervals directly.

Refactor LCOV generation into two passes:

1. source-line ranges create `DA`, `LF`, and `LH` records independently of
   symbols;
2. sized function symbols create `FN` and `FNDA` records using the declaration
   resolver from Phase 3.

This separation allows executed EFI and trampoline code to appear as line
coverage even when the enclosing labels have zero size.

### Phase 5 acceptance criteria

- Executed source lines outside all nonzero-sized symbols appear in LCOV.
- Unexecuted but mapped source lines remain in the denominator with zero hits.
- Execution in non-code sections or outside the ELF image is not attributed to
  source lines.
- Address maps are applied before image, source-line, and function lookup.
- Overlapping aliases do not double-count line hits.
- Existing C, inline-function, and byte-granularity tests retain their results.
- The discarded `copy_page.S` fixture remains absent.

## Phase 6: Define assembly function inventory policy

Do not infer a function merely because a zero-sized text label precedes another
symbol. First distinguish real function symbols from section labels and other
`STT_NOTYPE` names. Extend ELF loading, using BFD symbol and section metadata,
so each retained symbol records:

```text
ELF symbol type
binding and visibility
containing executable section
explicit versus inferred size
source-attribution confidence
```

For nonzero-sized function symbols, emit an LCOV function whenever an eligible
source interval intersects the symbol. Multiple functions may legitimately
share one assembly macro invocation line.

For zero-sized symbols:

- always allow their code to contribute to symbol-independent line coverage;
- emit an `FN` record only when the ELF identifies the symbol as a function and
  a range can be bounded within its executable section without crossing an
  equal-address alias;
- mark inferred extents internally and report them in diagnostics;
- otherwise omit the function record with an explicit reason.

Provide a machine-readable inventory or diagnostic mode with counts for:

- emitted sized functions;
- emitted inferred-size functions;
- zero-sized non-function labels;
- functions lacking any valid source interval;
- symbols removed because their section is not present or executable.

### Phase 6 acceptance criteria

- All 285 sized assembly routines from the reviewed Xen image are accounted
  for as emitted or explicitly diagnosed.
- The five hit IDT stubs and eight hit indirect thunks omitted by the reviewed
  LCOV become visible when covered by valid line intervals.
- Zero-sized EFI and trampoline code contributes line hits without arbitrary
  `FN` records.
- Equal-address aliases remain deterministic and cannot create overlapping
  inferred ranges.
- Linker-discarded `copy_page_cold` and `copy_page_hot` are not resurrected.

## Phase 7: Validate against the retained Xen trace

Regenerate LCOV from the retained trace and exact ELF using the reviewed runtime
mapping. Compare source records, line states, function records, and diagnostics
against a checked-in summary rather than committing the multi-gigabyte trace.

The validation must demonstrate:

- no regressions in the twelve x86 lines recovered by byte addressing;
- removal of the `l3t_unlock`, `ret_from_intr`, `handle_exception`, and
  `trap_nop` boundary misattributions;
- recovery of `common_interrupt` and `handle_ist_exception` function records;
- explicit accounting for the generated IDT and indirect-thunk functions;
- visible line coverage for executed EFI and trampoline code;
- stable results across repeated runs with the same ELF and address map.

Record the tool versions and ELF hash in the generated summary. Treat changed
compiler or linker output as a new fixture baseline rather than silently
updating expected totals.

## Proposed bisectable commit sequence

Each commit should build and pass all tests, use a short imperative subject and
body, and include Edgar's `Signed-off-by`.

1. `tests: Add assembly attribution fixtures`
   Add deterministic leading-padding, adjacent-sequence, macro-expansion,
   zero-sized-label, and discarded-section fixtures.
2. `syms: Parse DWARF line rows`
   Separate textual row parsing and sequence state from symbol attachment.
3. `syms: Ignore DWARF end sequences`
   Close intervals at `ET` rows without assigning those rows to code.
4. `lcov: Find function body locations`
   Scan forward for the first eligible declaration location in each sized
   symbol.
5. `lcov: Stabilize line hit aggregation`
   Prevent instruction width and aliased locations from inflating line counts.
6. `syms: Map DWARF line intervals`
   Apply normal row intervals across every overlapping sized symbol.
7. `coverage: Index executable ELF ranges`
   Add BFD-backed executable sections and address-indexed execution coverage.
8. `lcov: Emit symbol-independent lines`
   Build line records from executable DWARF intervals rather than symbol-owned
   line maps.
9. `syms: Classify assembly symbols`
   Retain ELF type, section, size provenance, and omission diagnostics.
10. `lcov: Complete assembly function inventory`
    Emit every defensibly mapped sized or bounded function and report the rest.
11. `tests: Validate Xen assembly coverage`
    Re-run the retained audit and check the summarized invariants.
12. `docs: Define assembly coverage semantics`
    Document line intervals, function inference, macro attribution, and known
    limits.

The first corrective release point is after commit 4: it removes false
end-sequence attribution and recovers functions with leading unmapped bytes.
The first complete line-coverage release point is after commit 8. Function
inventory claims should wait for commit 11's Xen validation.

## Explicit non-goals

- Treating every text label as a function.
- Extending a source row past a DWARF end-sequence marker.
- Recovering linker-discarded code as retained coverage obligations.
- Inventing distinct source lines for macro expansions when debug information
  maps them all to one invocation line.
- Equating object-code line or function coverage with source branch coverage or
  MC/DC.
- Committing the retained multi-gigabyte execution trace to this repository.
